# Screen UI rendering compatibility

This document describes the current implementation, not the intended feature set. A CSS declaration accepted by the parser is **not** automatically supported by every renderer.

## Rendering paths

| Path | Renderer | Purpose |
| --- | --- | --- |
| Editor preview | Browser DOM built from the compiled screen tree | Authoring and quick visual feedback |
| Browser player | Browser DOM built from the compiled screen tree | Browser playback and runtime tests |
| Desktop / packaged player | SDL-based Native renderer consuming the compiled screen tree | Native playback and distribution |

WebView2 is not a rendering path. Do not use it as the compatibility baseline.

## Current compatibility by layer

| Layer | Shared behavior | Important limits |
| --- | --- | --- |
| Canvas transform | `contain`, `cover`, and `stretch` use the shared reference-canvas transform; the editor can preview common aspect ratios | `cover` intentionally crops authored content; it does not reflow it |
| Geometry | The screen compiler calculates rectangles consumed by both paths; absolute placement and a subset of flex/grid are represented in that tree. Browser `h1`/`h2` margins are normalized in the tree; the DOM mount clears browser default margins and list markers. `vw` / `vh` lengths are resolved against the logical reference canvas and normalized to px before layout | This is a small layout engine, not browser CSS layout. General margins, min/max constraints, wrapping, full grid tracks, and several accepted properties are not fully calculated. Flex growth is limited to finite factors up to 1,000,000; grid tracks are limited to 2,000 |
| Selectors and focus order | Simple tag, class, id, `:hover`, `:focus`, and `:focus-visible` rules compile into separate hover, focus, and keyboard-visible-focus styles. `:focus-visible` includes matching `:focus` declarations in stylesheet order. For screen actions, settings inputs, and semantic buttons, authored `tabindex` orders positive values before zero and excludes negative values from keyboard navigation; semantic buttons/inputs default to zero. Compiled nodes carry a document-order `focusKey` so Native focus identity does not depend on HTML IDs. Paint stacking may sort the shared tree by `z-index`, while Browser DOM order, action order, and focus order retain the authored document order | Complex selectors are rejected during compilation instead of being silently ignored. `:focus` follows the focused screen action/input/button; `:focus-visible` applies only to keyboard-visible focus. Browser uses the DOM `:focus-visible` state; Native uses its keyboard navigation focus state. Native does not expose the Browser DOM accessibility tree; nonsemantic static elements do not become Native focus targets from `tabindex` alone |
| Paint | Both paths consume common colors, opacity, asset images, `contain`/`cover`/stretch image fitting, borders, stacking order, and text alignment. Browser and Native runtime fixtures verify `background-size`, nested opacity with overlapping children, and hover pixels | Rounded borders, shadows, transforms, transitions, clipping, and advanced fonts are not in the common subset and are rejected |
| Controls | Both paths support screen actions and the declared range/checkbox settings | Browser uses DOM controls; Native draws SDL controls. Their visual details and accessibility behavior are not identical |
| Image alternatives | The screen compiler requires `alt` on every authored `<img>`; Browser DOM preserves both descriptive values and empty `alt=""` for decorative images | Native consumes the same image geometry but does not expose an equivalent DOM accessibility tree or image alternative text |
| Form labels | Browser preserves `label[for]` and associates it with the real input, including the input inside an image-skinned control | Native draws the label text but has no OS accessibility tree or label-to-control activation |
| Save thumbnails | Browser composites the story stage into a 320×180 image before showing the save screen; Native caches the last fully rendered SDL story frame and writes `thumb-slot-N.png` when saving. Both omit the save/load overlay itself | Browser composites the background, sprites, images, dialogue panel/nameplate/text, choices, video, player controls, and simple effects; Native captures the actual renderer output. Browser custom CSS not represented by its stage compositor can differ from the live screen. Missing or damaged thumbnails leave the save itself loadable |
| Save-slot status | Both paths classify cards as empty, ready, corrupt, or incompatible and disable loading for every non-ready snapshot. The slot-card root receives `data-state` and its matching state style | Only `.class[data-state="empty|ready|corrupt|incompatible"]` selectors are supported, and they must match the save-slot template root; state selectors on nested fields or unrelated elements are rejected |

## Known silent-mismatch examples

- `Edit/screen-document.js` retains a broad syntax/security allowlist, then rejects known non-portable declarations and selectors before creating the shared tree.
- Background fit values and inherited opacity now have paired Browser/Native screenshot probes. Native `:hover` previously merged only for actionable elements; it now also follows the pointer across ordinary layout nodes.
- Native sibling drawing sorts by `z-index`; `<img object-fit="cover">` now crops the source image rather than stretching it.
- The shared title stylesheet no longer contains three complex selectors that were previously ignored by the common-tree compiler. Save slots pass their four-way state into the shared status field and support root-card styling for `empty`, `ready`, `corrupt`, and `incompatible` in both renderers.
- Editor preview success alone does not prove final visual parity: font rasterization, SDL widget appearance, device DPI, and real-window composition still require visual checks on each supported platform.

## Shared CSS property map

Only declarations that survive `NON_PORTABLE_PROPERTIES` in `Edit/screen-document.js` reach the shared tree. The table records the common subset and the consumer in each path; parser acceptance alone must not be used to infer renderer support.

| Property group | Shared-tree behavior | Browser DOM / Editor preview | Native SDL | Parity notes |
| --- | --- | --- | --- | --- |
| `position`, `left/right/top/bottom`, `width/height` | Resolved into shared `rect` values by the screen layout compiler | `buildScreenDom()` positions each element from the shared rect | Draws from the same rect after canvas scaling | `position` is limited to `relative`/`absolute`; it is not browser layout positioning. Absolute `right` and `bottom` insets are checked against raw Edge geometry, shared Browser rects/pixels, and Native SDL pixels in `game-screens.browser.cjs` and `game-screens-native.cjs` |
| `display`, `flex-direction`, `flex`/`flex-grow`, `justify-content`, `align-items`, `gap`/`row-gap`/`column-gap` | Flex children are resolved into rects. Numeric `flex` uses a zero main-axis basis; `flex-grow` keeps the authored/intrinsic basis and distributes only remaining space | CSS flow properties are intentionally omitted; DOM elements use compiled rects | Draws compiled rects | `display:none` produces a zero-size rect; absolute and hidden children do not participate in flow. Unequal `flex-grow` bases are covered by Browser and Native pixel fixtures. All eight accepted `justify-content` values (`start`, `flex-start`, `end`, `flex-end`, `center`, `space-between`, `space-around`, `space-evenly`) and all six `align-items` values (`stretch`, `start`, `flex-start`, `end`, `flex-end`, `center`) have raw Edge/shared rect comparisons and Browser pixels; Native pixels cover each justify outcome and each distinct align outcome, including alias pairs. A column with `align-items:flex-end`, `justify-content:space-between`, a 10px gap and a growing 120px cross-axis child in a 100px container is also paired against Edge CSS and SDL pixels; the shared rect preserves the authored 120px overflow width. Shrink and wrapping are not supported |
| `grid-template-columns`, `grid-auto-rows` | Supported grid tracks are resolved into rects; implicit rows repeat the configured row height and gap | CSS grid properties are omitted after compilation; overflow remains visible | Draws compiled rects without parent clipping | Only the track grammar accepted by the compiler is portable; paired Browser/Edge and Native SDL probes compare implicit-row overflow, equal intrinsic rows, and unequal 30px/10px auto-row contributions stretched inside a definite 100px grid. The second unequal row starts at 62.5px with a 5px gap. `overflow` declarations are rejected |
| `padding` and side values | Expanded and used as layout/content insets; compiled rectangles represent the outer box | Applied as scaled CSS padding with `box-sizing:border-box`, keeping the DOM outer size equal to the shared rect | Applied as text and image-content insets; background/border still use the outer rect | Percent and viewport units are normalized before renderer use |
| `background` / `background-color`, `background-image`, `background-size` | Color or one asset URL plus limited fit mode | Asset URLs are resolved; background image is centered and non-repeating | SDL draws color and asset texture, with `contain`, `cover`, or stretch | Browser and Native pixel fixtures use a red/green/blue 3:1 source in a square `cover` box and verify both side samples are the center green stripe, proving the red and blue source edges are cropped. Gradient and compound shorthand backgrounds are rejected |
| `color`, `font-size`, `line-height`, `text-align` | Inherited color/font size/line-height/text alignment are merged into node style. Unitless `line-height` remains a multiplier; `%` resolves against the declaring node's computed font size and is inherited as px; px values are fixed lengths; values are limited to 0–1,000,000 and zero is valid | Applied as CSS; horizontal alignment follows the content box; ordinary block text starts at the content-box top | SDL sets and restores the font line skip for each screen text node, including explicit zero, then draws horizontal alignment and starts ordinary block text at the content-box top | Font metrics, wrapping, and rasterization differ. Unspecified padding is zero in both paths. Center alignment uses the padded content box in both paths. Browser DOM and Native SDL fixtures verify unitless, percent, px, and zero line-height behavior, including a child with a different font size; paired runtime probes also cover horizontal centering and text origin with and without authored padding. |
| `border`, `border-width`, `border-color` | `border` expands to width/style/color | Applied as CSS | SDL draws the scaled solid rectangular border as four bands, without a renderer-specific 12px cap | Only `solid` borders and validated colors are accepted; paired tests cover a wide border |
| `opacity` | Merged through interaction state and inherited through the tree | CSS opacity composites the element subtree as one group | SDL composites the element subtree into a cached render target, then applies the group opacity | Overlapping descendants are covered by paired pixel tests. Disabled actions have an additional shared dimming rule; save-slot cards are exempt |
| `object-fit`, `z-index` | Image fit stays on the node; siblings are ordered by z-index | DOM retains authored order and applies CSS `z-index`; this keeps focus/action order independent from paint order | SDL crops/fits textures and sorts siblings | `fill`, `contain`, and `cover` are pixel-checked with the same 3:1 red/green/blue image in Browser shared DOM, raw Edge DOM, and Native SDL. `screen-focus-visual.browser.cjs` also samples overlapping siblings where the earlier `z-index:20` blue node must paint above the later `z-index:1` red node in Browser and Native. `z-index` is relative to siblings in the shared tree; nested descendants cannot escape an ancestor's paint order. No clipping or rounded corners |
| `accent-color` | Stored on input node style | Applied to the native DOM range control | Used for SDL range fill and focus marks | A `#ff00ff` unskinned range at value 1 is checked by computed style and a magenta fill pixel in shared Browser DOM and raw Edge DOM; Native checks its SDL range-fill pixel. The tests prove each runtime consumes the authored color, while control artwork remains visually distinct. See `game-screens.browser.cjs` and `game-screens-native.cjs`. |

The following matrix records the concrete Browser/Edge and Native evidence currently present in the named integration fixtures. Geometry assertions measure rects; paint assertions sample rendered pixels. The listed values are the tested scope, not a claim that every property combination or canvas scale is exhaustive.

| Property row | Browser / Edge evidence | Native SDL evidence | Scope measured |
| --- | --- | --- | --- |
| Position / geometry | `game-screens.browser.cjs`: absolute `right:13px` and `bottom:6px`, raw Edge rects vs compiled shared rects and pixels | `game-screens-native.cjs`: `right-position-child`, `bottom-position-child` pixels | Right and bottom inset placement |
| Flex | `game-screens.browser.cjs`: data-driven raw Edge vs shared rects and pixels for all 8 `justify-content` and 6 `align-items` values; existing overflow, growth, cross-axis probes | `game-screens-native.cjs`: pixel samples for all 8 justify values and all 6 align values, plus `flex-grow-probe`, `flex-cross-axis-probe`, `flex-overflow-probe` | Placement of each accepted value; Native alias values are individually sampled, even when they share an outcome |

| Border | `game-screens.browser.cjs`: `wide-border-host` pixel bands | `game-screens-native.cjs`: `wide-border-probe` 30px border pixels | Solid border beyond prior Native 12px cap |
| Opacity | `game-screens.browser.cjs`: overlapping opacity group and hover-state pixels | `game-screens-native.cjs`: `opacity-group` and hover pixels | Group compositing and interaction opacity |

| Accent-color | `game-screens.browser.cjs`: computed `rgb(255, 0, 255)` and magenta fill pixel in shared DOM and raw Edge DOM | `game-screens-native.cjs`: magenta pixel in unskinned SDL range fill | Authored accent consumption at range value 1 |

The Native text alignment path must calculate `center` from `rect.x + padding-left` through `rect.right - padding-right`, matching CSS `text-align`'s content box. Centering against the outer rectangle misaligns text whenever left and right padding differ. Missing padding declarations resolve to zero; Native must not add an implicit inset. Ordinary `div`/`span` text uses the content-box top edge in Browser CSS; Native must not vertically center it by default.

## Compatibility policy to enforce

1. Keep the parser allowlist for safety, and maintain the separate renderer capability contract enforced during compilation.
2. Treat the compiled screen tree as the semantic source of truth. Geometry and interaction state must not be reinterpreted differently by each renderer.
3. At save/preview/package time, identify unsupported selectors and declarations with screen ID, HTML/CSS file paths, selector, CSS rule or declaration line/column, property, and target renderer. `compileGameScreens()` adds file context, while the shared compiler reports the exact declaration position for property errors.
4. Add each newly supported visual feature to both renderers and to a paired Browser/Native regression test before documenting it as common.
5. Keep Browser-only authoring features explicitly target-scoped; do not imply that they are portable to Native builds.

The evidence matrix describes the current tested common subset and its limits. Add paired Browser/Native probes when expanding accepted values or adding a property, and inspect the packaged Native player when visual acceptance depends on integration details not represented by these fixtures.


### Flex overflow alignment

When flex items and fixed gaps exceed the container main axis, `center` and `end` / `flex-end` retain negative free space: centered items overflow equally at both edges, while end alignment places the overflow before the first item. Edge measurements show that `space-between`, `space-around`, and `space-evenly` all fall back to start alignment when free space is negative. Browser Edge reference geometry covers all three values; Native SDL pixels cover centered overflow. Browser Edge and Native SDL pixel fixtures cover centered overflow; shared geometry must keep this behavior. Flex shrink and wrapping remain unsupported.


### CSS gap shorthand and longhand cascade

The shared screen stylesheet accepts `gap` with one or two nonnegative lengths. One value sets both row and column gaps; two values set row gap then column gap. Explicit `row-gap` and `column-gap` declarations override the corresponding shorthand axis according to stylesheet declaration and rule order. Edge and Native SDL fixtures verify a grid with `gap:10px 20px`, `column-gap:30px`, and `row-gap:5px`.


### Grid implicit row sizing

Grid parents derive intrinsic height from every participating implicit row and its row gaps. An explicit `grid-auto-rows` fixes each implicit track to that configured size. Without it, each auto track starts at the largest intrinsic item contribution in its row and stretches evenly to fill a definite grid height; item dimensions that are explicitly authored remain unchanged. Edge and Native SDL fixtures verify a 45px auto-height two-row grid and the 52.5px second-row offset in a 100px grid with a 5px gap.
